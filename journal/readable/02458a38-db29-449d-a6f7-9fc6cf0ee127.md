**How it works:**

1. **Keep every changeable value in one dictionary** (`params`): the model parameters (K, n, r_max, r_basal) and the axis limits (x min/max, y min/max).
2. **One `redraw()` function** rebuilds everything from `params`:
   - It makes the x values with `np.linspace` (or `np.logspace` for a log axis).
   - It calls `transcription_rate` on the whole array at once.
   - It updates the curve with `line.set_data(x, y)`.
   - It sets the axes with `ax.set_xlim`, `ax.set_ylim` and `ax.set_xscale("log")`.
3. **Each widget changes `params` and calls `redraw()`.** For example, `TextBox(...).on_submit(callback)` runs the callback when you press Enter.
4. **Bad input is caught, not crashed on.** Your model already raises `ValueError` for things like n ≤ 0. `redraw()` catches it and shows the message in red under the plot, the same way `interactive.py` re-prompts.
5. **Layout:** `fig.subplots_adjust(bottom=0.42)` leaves room at the bottom. Each widget gets its own small area from `fig.add_axes([left, bottom, width, height])`, measured as fractions of the window.

**Things to know:**
- Keep references to the widgets, as the `boxes` dict does. Otherwise Python can delete them and the controls stop responding.
- A log axis can't start at 0, so in log mode the code raises x min to 1e-6.
- matplotlib's own toolbar (zoom/pan) also works on the plot; you get it for free.

A minimal backend:
```python
from fastapi import FastAPI
import numpy as np
from gene_expression import transcription_rate

app = FastAPI()

@app.get("/api/hill")
def hill_curve(K: float = 1, n: float = 2, kind: str = "repressor",
               x_min: float = 0, x_max: float = 5):
    x = np.linspace(x_min, x_max, 500)
    y = transcription_rate([(x, K, n, kind)])
    return {"x": x.tolist(), "y": y.tolist()}
```

## `app.py`: the web API
It doesn't do any maths of its own. Each endpoint passes the inputs to your existing functions and sends the result back as JSON.

| Endpoint | Calls | Purpose |
|---|---|---|
| `GET /api/health` | `transcription_rate` | Is the server up, and can it reach your code? |
| `POST /api/steady-state` | `hill`, `transcription_rate`, `mrna_steady_state`, `protein_steady_state` | Same as `interactive.py` |
| `POST /api/rate-curve` | `transcription_rate` with an array of x values | Data for the r(x) graph, with x range and optional log x-axis |
| `POST /api/gillespie` | `gillespie` | m(t), p(t) trajectory, with optional autorepression |
| `POST /api/gillespie-stats` | `steady_state_stats` | Simulated mean and Fano factor, next to the theory values |
| `POST /api/cascade` | `cascade_stats` | Mean and Fano factor per gene |

- **Bad values:** inputs like n ≤ 0 return **400** with your model's own error message. Missing fields or wrong types return **422**.
- **numba on Vercel:** the app points numba's cache at `/tmp` automatically when running there, which avoids the read-only file problem.
- **Size limits:** curves are capped at 2,000 points and trajectories at 5,000, so responses stay under Vercel's size limit.
- **Your model files are unchanged.** One thing I noticed: `cascade_stats` doesn't check its inputs, and `k_r1 = 0` makes it divide by zero. `app.py` now rejects that and other invalid cascade inputs before calling it.
